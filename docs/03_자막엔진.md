# 유미미 믹스 리믹스 자막 엔진 분석 · 한글화 설계 (2026-10-01)

영문 패치(Supper, `work/en/yumimiremixtools`)가 **원본에 없던 자막 기능**을 새로 만든 구조를 정리하고, 한글(2바이트, 수천 음절)을 얹는 방법을 설계한다.
다른 게임에 옮겨 쓸 수 있게 ①게임 엔진 쪽(주소·훅, 게임마다 다시 찾아야 함) ②자막 시스템 쪽(형식·렌더러, 그대로 재사용)을 나눠 적는다.

---

## 1. 전체 그림

```
script_scene.csv (영어 칸: 글 줄 + #명령)
   │  ymm_scriptimport → spec_scene.txt (파일별 영역: SETFILE·SETSOUNDCOUNT·STARTSTRING…)
   │  ymm_scriptbuild  → 스크립트 바이트코드로 컴파일
   ▼
장면 파일(*.DAT/*.CUT) 맨 앞에 «SUBS 블록»을 덧붙임  ← 원래 파일 뒤로 밀림
   │  (실행 중) 장면 적재 훅이 SUBS 를 알아보고 RAM 으로 복사, 장면 데이터 기준 주소를 블록 크기만큼 밀어 줌
   ▼
소리 재생 훅 → 소리 번호 N 의 스크립트를 흐름(stream) 0 에서 시작 / 장면 시작 → start 스크립트를 흐름 1 에서
   │  흐름 해석기(매 프레임): 시각 대기·끄기·자리·색·정렬·동기화 명령 실행, 글을 만나면 «자리(slot)»에 배정
   ▼
자리(아래 0 / 위 1) 문자열 → 경칭 +A+B+ 고르기 → 자동 줄바꿈 → 글자마다 VDP1 스프라이트 명령(16×14 4bpp)
   │  명령 목록은 VDP1 VRAM 0x17000 에 두 벌(A/B 교대), 게임 명령 목록 끝의 «끝 표시»를 «점프 명령»으로 바꿔 이어 붙임
   ▼
화면(원래 그림 위에 겹침)
```

- 실행 파일 = `SATANIME.BIN`(적재 0x06012000). 원본 0x46748 B → 영문 0x57398 B(끝 0x06069398). 새 코드·데이터는 **0x06058800‥0x0606C000** 빈 곳(`.area`).
- ⚠남은 RAM: 0x06069398‥0x0606C000 = **약 11 KB**. 한글 글꼴 전체(수천 음절)는 못 둔다 → 장면별 글리프(아래 4장).

## 3. 자막 시스템 쪽 — 형식 (그대로 재사용)

### 3-1. SUBS 블록 (장면 파일 맨 앞)
```
+0  'SUBS'
+4  u32 블록 크기(4 정렬) — 이만큼 장면 데이터가 뒤로 밀림
+8  u32 소리 수 N (원본 C334B 가 없는 소리를 트는 버그 막이)
+12 u32 오프셋 × (1 + N + 추가)   ★«+12» 기준, 0 = 없음
    순서 = [장면 시작 스크립트, 소리 0‥N-1, 추가(STARTSCRIPT 로 부르는 것)…]
    (spec_scene.txt 는 소리들 → start → 추가 순으로 적고, 빌더가 start 를 맨 앞으로 옮김)
이어서 스크립트들(정렬 없음), 끝을 4 정렬
```

### 3-2. 스크립트 바이트코드 (흐름 해석기)
| 코드 | 인자 | 뜻 (CSV 표기) |
|---|---|---|
| 00 | — | 스크립트 끝 |
| F0 | u16 프레임(60fps×시간배율) | 흐름 시계가 이 값이 될 때까지 대기 (`#w(초)`) |
| F1 | — | 현재 자리 자막 끄기 (`#off()`, `#woff(초)` = F0+F1) |
| F2 | u8 0=아래 1=위 | 대상 자리 (`#slot(bottom/top)`) |
| F3 | u8 0=기본 1=카라오케 | 색 (`#pal(std/karaoke)`) |
| F4 | u16 시작, u16 끝(−끝 보정) | 카라오케 구간 시각 — **문자열 바로 뒤에만** (`#kseg(a,b)`) |
| F5 | u8 0=가운데 1=왼쪽 | 정렬 (`#align`) |
| F6 | u8 종류(0 소리·1 CD 재생·2 CD 대기), u16 목표값, u16 새 시계 | 동기화 (`#sync`) |
| F7 | u8 흐름, u8 스크립트 번호 | 다른 스크립트 시작 (`#startscript`) |
| 그 밖 | 00 까지 | **문자열**(글꼴 표 코드) → 대상 자리에 배정 |

- 문자열 안 제어: E0 줄바꿈(`\n`) · E1/E2 카라오케 구간 표시(`<` `>` — 글자 아님, 바이트 위치가 F4 구간과 짝) · E3 경칭 구분(`+A+B+`, 옵션에 따라 앞/뒤만 남김) · 4F 공백.
- 컴파일 규칙(YmmScriptReader): 줄 머리 `#` = 명령(명령이 문자열을 끊는다) · `//` 주석 · 빈 줄 무시 · `*` 버림 · 글 줄은 **이어 붙임**(줄바꿈 아님).
- ✅검증(`tools/subs.py`): 적용본 SUBS 블록 837개의 스크립트 **1,155개 전부**가 CSV 영어 칸 «조각»(#줄 사이 글 묶음)과 순서대로 1:1 일치 → **한국어는 컴파일된 스크립트의 문자열만 갈아 끼우면 된다**(시각·명령 바이트는 그대로, 빌드 도구 불필요).

### 3-3. 렌더러
- 자리 2개(아래 0 = 화면 아래 기준 y 200, 위 1 = y 24 기준), 자리마다 문자열 최대 **0xC0 B**, 줄 최대 4, 줄 간격 16.
- assignRenderBufString(적용본 0x06068A00 부근): ①경칭 거르기 → subStringPrepBuf ②**wordWrapString**(폭 288px, 적용본 호출 풀 상수 **0x06068AA4**) ③F4 구간 복사 ④readSubData(줄 폭·카라오케 x 계산).
- 글자 1개 = VDP1 스프라이트 명령 1개(최대 0xC0 개): CMDSRCA = (0x1A800 + 코드×0x70)/8, 크기 16×14, 색 뱅크 = CRAM 0x600/32 + 팔레트(0 기본·1 전경·2 배경·3‥6 카라오케 그라데이션). 카라오케는 사용자 클리핑으로 한 글자를 세로 조각으로 나눠 색을 바꿈.
- 글꼴: 16×14 4bpp 160칸(코드 0x00‥0x9F), RAM 원본 **0x0605883C**(= fontBitmap), 폭 표 **0x0606203C**(160 B), 커닝 행렬 **0x060620DC**(160×160 부호 바이트, [앞 글자×160 + 이 글자]), getCharKerning 0x060684DC.
  - 글자 칠: F = 흰 몸, 1 = 테두리, 2 = 오른쪽 아래 그림자(팔레트 std: 0 투명·2 = #222222).
  - ★**코드 0x51‥0x9B(75칸)** = 기울임꼴 자리(빌더가 기울임을 꺼서 글에서 안 씀, 칸·폭·커닝만 남음) → 한글 캐시 칸으로 쓸 수 있다.
- 명령 목록 VRAM: 0x17000(A)·0x18800(B) 교대, 점프 명령 0x16FE0. 일시정지 그림 0x11000‥0x12180.

## 4. 한글화 설계 (영문 적용본 직접 수정)

### 4-1. 코드
- 한국어 음절 = **2바이트** `A0+(i/200), 1+(i%200)` — i = 그 장면 글리프 번호. 둘째 바이트는 00·E3 을 피한다(경칭 거르기가 바이트 단위로 00·E3 을 봄). 첫 바이트 A0‥DF 는 글꼴 밖이라 영어 코드와 안 겹침.
- 숫자·로마자·부호(. , ! ? 등)는 기존 1바이트 코드 그대로.

### 4-2. 음절 → 캐시 칸 바꾸기(새 SH-2 함수 «remap»)
- 자리 배정 때 경칭 거르기 뒤, **줄바꿈 직전**에 끼운다: 0x06068AA4 의 wordWrapString 주소를 remap 주소로 바꾸고, remap 이 끝에 wordWrapString 으로 넘어감(r4 원본·r5 대상·r6 폭 보존). 자리는 r5(subStringBufA/B)로 가림.
- remap: 준비 버퍼를 제자리에서 2바이트 → 1바이트 캐시 코드로. 캐시 칸 = 아래 자리 0x51‥0x84(52칸) · 위 자리 0x85‥0x9B(23칸), 문자열마다 그 자리 칸을 처음부터 다시 씀(같은 음절은 같은 칸).
  새 칸마다 글리프(장면 글리프 표, 2bpp 56 B → 4bpp 112 B 로 펼침: 0 투명·1 테두리·2 그림자·3→F)를 **VDP1 0x25C1A800+코드×0x70 과 RAM 글꼴 0x0605883C+코드×0x70 둘 다**에 씀 → 장면마다 글꼴을 다시 올려도 캐시가 안 지워짐(loadFont 손대지 않음).
- 그 뒤 줄바꿈·폭·커닝·카라오케·그리기는 전부 1바이트 코드로 **기존 코드 그대로** 돈다.
- 폭 표 0x51‥0x9B = 한글 전진폭(예 13), 커닝 행렬의 0x51‥0x9B 행·열 = 0 (정적 패치).
- 끝나면 자리당 칸 한도(52/23)를 **빌더가 쓰는 순간** 검사(넘으면 오류 — 문장 나누기).

### 4-3. 장면 글리프
- 장면마다 그 장면 한국어에 나오는 음절만 2bpp 16×14(56 B)로 SUBS 블록 뒤에 붙임. 블록 끝 8 B = `u32 복사 크기(문자열 부분)` + `'HANG'`.
- 새 적재 함수(0x0601255A 풀 상수를 새 주소로): 끝 표시가 있으면 복사 크기만 subtitleBlockData(0x2000 한도)로 복사, 글리프 주소 = 0x20200000 + 복사 크기 를 변수에 저장, 장면 기준 주소는 **전체 크기**만큼 밈(나머지는 영문 함수와 같음).
- 글리프는 Low RAM(장면 적재 영역) 그대로 읽는다 — 장면 데이터 앞이라 장면이 끝날 때까지 살아 있음.
- ✅장면 적재 한도(원본 0x06019DC0): 파일 앞 **min(크기, 0xF8000)** 을 0x20200000 에 올린다(파일 이름 C117·C127 만 0x50000). 1 MB 넘는 장면 26개는 앞 창만 올리고 소리(PCM)는 따로 읽음.
  - 장면 파일 = `'ABLK'` + [부장면 오프셋(최상위 니블 0) + PCM 오프셋들(최상위 비트 1)]… + 끝(0xF…) 목록, 이어서 부장면 데이터·PCM. (oneshot 형식은 ABLK 없이 부장면 하나)
  - 창(0xF8000)에 걸리는 32개 파일 모두 부장면(그림·스크립트) 데이터는 **앞 0x2D000 안**에서 끝나고 나머지는 PCM → SUBS 가 커져도 밀려나는 건 PCM 꼬리뿐(영문 패치도 C318 을 창 밖으로 0x130 B 밀었음).
  - ⚠경계 파일: 원래 창 안인데 한글로 커지면 창을 넘는 파일(C477B 여유 4 KB · C560 9.5 KB 등) → 빌더가 «원래 ≤ 0xF8000 < 새 크기» 를 경고하고, 필요하면 글리프를 1bpp(28 B)로 줄이거나 그 장면 문장을 줄인다.
- 영문 SUBS 블록은 0xA0‥0x588 B 로 작다. 한국어 블록 ≈ 문자열(영어와 비슷) + 음절 수 × 56 B(2bpp).

### 4-4. 디스크
- 장면 파일이 커짐(문자열 차 + 글리프) → **ISO 전체 재배치**(영문 패치도 discaster 로 전부 다시 배치):
  - 적용본 트랙 1 = 데이터 파일 LBA 40‥134990 이 빈틈없이 이어지고, 150섹터 뒤 CD-DA «포인터 파일» CDDA1‥3(디렉터리 기록이 트랙 2‥4 를 가리킴), PVD 볼륨 크기 = 전체 이미지 섹터 수(165,443).
  - ⇒ 파일을 같은 순서로 다시 이어 쓰고, 디렉터리 LBA·크기, CDDA 포인터(새 트랙 시작), PVD 크기, 섹터 헤더·EDC/ECC(`anearth tools/cdmode1`)를 새로. 배포는 트랙별 bin(Redump 4트랙) 기준 xdelta.
- SH-2 어셈블 = aww `sh2asm.Asm`(사이버 돌 hook8 의 확장 A 클래스 재사용).
- SATANIME.BIN 도 커짐(remap·적재 함수 ~1 KB, 0x06069398 뒤).

### 4-5. 한글화 범위 밖(따로)
- 선택지(script_choice 168행): 영문 패치가 **장면 그림(타일맵)** 에 선택지 글을 구워 넣음(ymm_scriptbuild prepAndExportChoiceScene, 글꼴 font/choice) → 장면 그림 압축 풀기·다시 굽기(YmmScene/YmmCompress 이식) 필요.
- 일시정지 메뉴 그림(rsrc/pause_menu_*.bin — SATANIME 안), 제목 메뉴·저장 안내·인터페이스·퍼즐 그림, 엔딩 크레디트.
